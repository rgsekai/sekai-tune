# Security Policy

## Supported Versions

Security fixes are provided only for the latest stable release of Sekai Tune. Older versions are not maintained.

| Version | Supported |
| :--- | :--- |
| [Latest Release](https://github.com/rgsekai/sekai-tune/releases/latest) | :white_check_mark: |
| Older releases | :x: |

If you encounter a potential security issue, please verify whether it still occurs on the latest release before reporting.

---

## Reporting a Vulnerability

If you discover a security vulnerability in Sekai Tune, please disclose it responsibly using GitHub's **Private Vulnerability Reporting**:

1. Navigate to the **[Security tab](https://github.com/rgsekai/sekai-tune/security)** on GitHub.
2. Click on **[Report a vulnerability](https://github.com/rgsekai/sekai-tune/security/advisories/new)** to open a private advisory draft.

> [!CAUTION]
> **Do not** report security vulnerabilities via public GitHub issues, discussions, or pull requests.

---

## What to Include in Your Report

To help assess and resolve the issue quickly, please provide:

- A clear summary of the vulnerability and its potential security impact.
- Step-by-step instructions or a minimal proof-of-concept to reproduce the behavior.
- The app version and architecture (e.g., `1.1.9` / `gms-mobile-arm64`).
- The device model and Android version tested on.

> [!IMPORTANT]
> **Never include real credentials, personal tokens, private keystores, API keys, or real user data in your report.** Use dummy or sanitized placeholder values instead.

---

## Response Expectations

Sekai Tune is developed and maintained by a solo independent developer in personal time. 

- I will do my best to review and respond to valid vulnerability reports within **7 days**.
- While I cannot guarantee immediate resolution timelines or commercial-grade SLAs, genuine security issues will be prioritized and patched in the next release cycle.
